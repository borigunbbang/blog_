**오늘의 주제**: 자동화, 워크플로, AI Agent의 차이를 이해하고 실제 실행 기록으로 결과를 확인하는 방법.

### 먼저 전체 요약

| 방식 | 특징 |
|---|---|
| 자동화 | 미리 정한 규칙이 충족되면 정해진 일을 수행한다 |
| 워크플로 | 여러 작업을 노드와 연결선으로 이어 실행 순서를 설계한다 |
| AI Agent | 목표와 도구를 바탕으로 상황에 맞게 다음 행동을 선택할 수 있다 |

- AI가 일을 했다는 사실만으로는 충분하지 않다. 어떤 데이터와 권한으로 무엇을 했는지 **실행 기록**으로 확인해야 한다.
- 명확한 조건은 IF 같은 고정 규칙으로 처리하고, 문맥 해석이 필요한 부분에 AI를 활용하는 편이 안전하다.
- 자동화 도입 여부는 편리함만 보지 말고 확인된 사실, 모르는 점, 권한 범위, 검증 방법을 함께 따져야 한다.

## 1. 다음 행동을 누가 정하는가?

### 세 가지 방식

| 방식 | 다음 행동을 정하는 주체 | 장점 | 주의점 |
|---|---|---|---|
| 사람이 직접 지시 | 매 단계마다 사람 | 통제가 쉽다 | 반복 작업이 많다 |
| 고정 워크플로 | 미리 정한 순서와 분기 | 예측과 점검이 쉽다 | — |
| AI Agent | 이전 결과를 참고해 도구·다음 행동을 동적으로 선택 | 유연하다 | 확인과 제한이 중요하다 |

### 비교할 때 볼 기준

- **통제**: 실행 가능한 행동과 권한을 제한할 수 있는가?
- **관찰 가능성**: 입력, 출력, 실행 단계, 오류가 기록으로 남는가?
- **승인**: 메일 발송이나 데이터 변경 전에 사람의 승인을 받을 수 있는가?

> 💡 핵심: Agent가 더 똑똑해 보이는지가 아니라, 업무에 필요한 **자율성과 통제 수준**이 맞는지를 판단한다.

## 2. 자동화 규칙과 워크플로 비교 기준

### 워크플로의 기본 구성

| 구성 요소 | 의미 | 예시 |
|---|---|---|
| 노드(Node) | 하나의 작업 단위 | 메일 읽기, API 요청, AI 요약, 스프레드시트 기록 |
| 연결(Connection) | 작업이 실행되는 순서를 잇는다 | — |
| 트리거(Trigger) | 워크플로를 시작하는 조건 | 버튼 클릭, 일정, 새 메일 |
| 분기(Branch) | 조건에 따라 다른 경로로 보낸다 | — |
| 실행 기록(Execution) | 실제 실행 결과와 오류를 확인하는 기록 | — |

### 도구를 비교할 때

- **통제**: 실행 흐름과 권한을 얼마나 세밀하게 설정할 수 있는가?
- **관찰 가능성**: 실행 과정과 오류를 쉽게 확인할 수 있는가?
- **이식성**: 다른 환경으로 옮기거나 설정을 내보낼 수 있는가?
- **비용**: 사용량, 호스팅, API 비용이 어느 정도인가?
- **데이터 경로**: 데이터가 어디서 들어와 어디로 전송되고 저장되는가?

Zapier, Make, n8n은 자동화 도구의 예시다. 이름을 외우는 것보다 각 도구가 흐름을 어떻게 구성하고 실행 결과를 어떻게 보여 주는지 비교하는 것이 중요하다.

## 3. n8n에서 두 노드짜리 워크플로 실행하기

실습 목표는 직접 설계한 실행 흐름과 실제 실행 결과를 비교해 보는 것이다.

```
Manual Trigger → HTTP Request → 공개 Wikipedia 요약 API 응답 확인
```

1. Manual Trigger를 눌러 실행을 시작한다.
2. HTTP Request 노드가 외부 API에 요청을 보낸다.
3. 실행 결과에서 상태 코드와 응답 본문을 확인한다.
4. Executions 화면에서 실행 성공 여부와 각 단계의 결과를 확인한다.

> 워크플로를 화면에 그려 두는 것과 실제로 성공적으로 실행되는 것은 다르다. 설계만 보지 말고 실제 실행 기록과 응답 데이터를 확인해야 한다.

## 4. 코딩 에이전트와 n8n CLI 활용

코딩 에이전트(예: Claude Code)로 워크플로 정의를 만들고, n8n CLI로 등록하거나 실행을 확인하는 흐름을 살펴봤다.

- 생성된 워크플로 JSON을 읽어 어떤 노드와 연결이 있는지 확인한다.
- 내용을 검토한 뒤에만 워크플로를 생성하거나 실행한다.
- n8n UI에서 실행하고 실행 기록을 확인한다.
- CLI와 MCP는 기능을 호출하거나 결과를 확인하는 서로 다른 방식이다. MCP를 연결하면 에이전트가 추가 도구를 사용할 수 있지만, 권한 범위와 수행 행동을 검토해야 한다.

> ⚠️ 주의: 에이전트가 만든 설정을 무조건 실행하지 말고 변경 내용과 권한을 먼저 확인한다.

## 5. 워크플로 안에 AI Agent 넣기

### 예시 흐름

```
Gmail에서 오늘의 메일 가져오기 → AI Agent로 요약하기 → Google Sheets에 결과 추가하기
```

### 검토할 내용

- 메일을 실제로 읽는 계정과 권한이 무엇인지 확인한다.
- 원본 메일과 AI가 만든 요약을 구분해서 확인한다.
- 어떤 데이터가 AI 서비스로 전송되는지, 민감한 내용이 포함되는지 살핀다.
- Google Sheets에 어떤 정보가 기록되는지 확인한다.

### IF와 AI Agent의 역할 차이

| 노드 | 적합한 상황 | 예시 |
|---|---|---|
| IF 노드 | 조건이 명확할 때 | "점수가 80 이상이면 통과" |
| AI Agent | 문맥을 읽거나 애매한 요청을 해석할 때 | 메일 요약, 모호한 요청 해석 |

> 💡 좋은 구성은 모든 일을 AI에게 맡기는 것이 아니다. 명확한 규칙은 IF로 처리하고, 해석이 필요한 부분에 AI를 사용한다.

## 6. 자동화를 도입할지 판단하기

자동화를 무조건 도입하거나 거절하기보다, 확인한 사실과 아직 모르는 점을 구분해 판단한다.

| 기준 | 내용 |
|---|---|
| 확인된 사실 | 실습이나 로그를 통해 실제로 확인한 내용 |
| 모르는 점 | 아직 시험하지 않았거나 결과가 불확실한 내용 |
| 권한 범위 | 자동화가 읽기, 수정, 전송 중 무엇을 할 수 있는가 |
| 검증 신호 | 성공 여부를 어떤 기록이나 결과로 확인할 수 있는가 |

### 판단 문장 예시

> "이 작업은 반복적이고 규칙이 명확하므로 자동화 도입을 검토한다. 다만 데이터 접근 범위와 실패 시 복구 방법은 아직 확인하지 않았다. 먼저 제한된 샘플로 시험하고, 실행 기록과 결과가 일치하는지 확인한 뒤 범위를 확대한다."

판단은 '좋아 보인다'에서 끝내지 않는다. 어떤 조건이 충족되면 도입하고, 어떤 문제가 발견되면 보류하거나 다시 검토할지 기준을 적는다.

## 7. 선택 실습: n8n 직접 운영하기

자동화 도구를 내 컴퓨터나 서버에서 직접 운영할 때 데이터와 실행 환경이 어떻게 관리되는지 알아보는 단계다.

| 기술 | 역할 |
|---|---|
| Docker | 프로그램과 실행 환경을 컨테이너로 묶어 실행하도록 돕는다 |
| `127.0.0.1:5678` | 보통 내 컴퓨터에서 실행 중인 n8n에 접속할 때 쓰는 주소와 포트 |
| Volume | 컨테이너를 다시 만들어도 데이터가 유지되도록 별도 저장 공간을 연결한다 |
| SQLite / PostgreSQL | 실행 정보와 설정 등을 저장하는 데이터베이스 선택지 |
| Redis와 Queue Mode | 작업을 대기열로 관리하고 실행을 분산하는 구성에 활용 |
| Kubernetes | 여러 컨테이너를 배포하고 운영하는 데 사용하는 시스템 |
| 백업과 권한 | 데이터 저장 위치, 접근 가능한 사람, 장애 시 복구 가능성을 확인 |

> 기술 이름을 모두 외우는 것이 목적은 아니다. 자동화가 어디서 실행되는지, 데이터가 어디에 남는지, 권한과 백업을 어떻게 관리하는지 이해하는 것이 중요하다.

## 8. 마지막 정리

- 자동화는 규칙 실행, 워크플로는 미리 설계한 실행 흐름, AI Agent는 상황에 따라 다음 행동을 선택하는 방식이다.
- 설계 화면만 보지 말고 실제 실행 기록과 원본 응답을 확인한다.
- 명확한 조건은 IF 같은 규칙으로, 해석이 필요한 부분은 AI로 처리한다.
- 메일·문서·외부 서비스 연결에서는 권한과 데이터 전송 경로를 반드시 확인한다.
- 자동화 도입 여부는 확인된 사실, 미확인 사항, 권한, 검증 기준을 바탕으로 결정한다.
