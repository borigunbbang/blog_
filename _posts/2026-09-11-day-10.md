## w, b에 대한 설명 (가중치 / 편향)

w는 입력값을 보고 "이 입력을 얼마나 반영할지" 결정하는 값. 그런데 w만 있으면 문제가 생김.

**예시**: AI가 사람의 공부시간 x를 보고 시험점수 y를 예측한다고 하면, 정답 데이터가 대충 이렇다고 해보자.

| 공부시간 x | 실제 점수 y |
|---|---|
| 1시간 | 50점 |
| 2시간 | 60점 |
| 3시간 | 70점 |

이걸 단순하게 표현하면 `y = 10x + 40`이 됨. 왜냐하면 공부 1시간 → 10×1+40=50, 2시간 → 10×2+40=60, 3시간 → 10×3+40=70이기 때문.

여기서 `w = 10`은 공부시간이 1시간 늘어날 때 점수가 얼마나 변하는지를 나타냄. 그런데 `10x`만 사용하면 `y = 10x`이니까 1시간→10점, 2시간→20점, 3시간→30점밖에 안 됨 — 실제 데이터와 완전히 다름. 그래서 전체적인 기준점을 이동시키기 위해 b를 넣는 것.

`y = wx + b` — 여기서 `b = 40`을 넣으면 "공부시간이 0시간이어도 기본적으로 40점 정도의 기준이 있다"라는 식으로 전체 값을 조절할 수 있음.

그러니까 w와 b의 역할이 다름:

- **w**: "x가 변하면 y를 얼마나 변화시킬까?"
- **b**: "그런데 애초에 기본적으로 어느 위치에서 시작할까?"

```
        y
        ↑
   70   |          ●
   60   |       ●
   50   |    ●
   40   | ●  ← b
        |
        +----------------→ x
```

w는 선의 기울기를 바꾸고, b는 선 전체를 위아래로 움직임.

**AI 학습에서 중요한 부분**: AI가 처음부터 "w는 10이고 b는 40이구나!" 하고 아는 게 아님. 처음에는 w와 b가 임의의 값으로 시작하고, **예측 → 실제 정답과 비교 → 오차 계산 → w와 b 조정**을 반복하면서 적절한 w와 b를 찾아감.

정리하면:

- w = 입력을 얼마나 반영할지
- b = 전체적인 기준을 어디에 맞출지
- AI는 w와 b를 계속 조정해서 정답에 가까운 예측을 만든다
- ⇒ w, b는 정답과의 오차를 줄이기 위해 값을 계속 조정하다가, 정답과 가까워지면 상수(변하지 않는 고정값)가 됨

모든 LLM에서 레이어와 레이어를 넘어가는 구간마다 비선형함수 계산값이 다 적용됨.

## 오늘 수업 필기: AI 이해와 사용

### 이미지 분야

AI는 이미지로부터 시작됐음 (FC 구조). 처음에는 이미지도 이런 식으로 뽑아냈다가 이후 찾아낸 게 CNN.

**컬러 이미지 예시**: 컬러 이미지는 RGB 세 장의 이미지가 겹쳐져서 만들어진 것 ⇒ 빨간색 행렬 한 장, 녹색 행렬 한 장, 파란 행렬 한 장. 이 한 장 한 장을 **채널**이라 함.

3×3 필터를 이용해 한 칸 한 칸 뽑아냄. 필터 한 칸 한 칸엔 웨이트값이 들어있음 ⇒ 영역 단위로 픽셀을 만드니까 공간 정보를 살리게 됨. 이게 계속 누적되어 여러 사진들을 뽑아내다 보면 비슷한 특징을 가진 것들이 나오게 됨 (예: 강아지 사진을 많이 뽑아내면 강아지의 특징들이 나와서 더 잘 구분할 수 있게 됨).

이미지와 필터가 겹쳐져서 대응하는 픽셀마다 곱하고, 나온 값을 다 더한 뒤 우측으로 이동시켜 같은 연산을 적용.

### 과적합

기계 학습 모델이 훈련 데이터에 지나치게 최적화되어 새로운 데이터에 대한 예측 성능이 떨어지는 현상. 규칙을 이해하는 대신 주어진 훈련 데이터를 통째로 외워버리는 현상.

- 데이터를 학습데이터(러닝데이터)와 테스트 데이터로 나눠서 러닝 데이터로만 학습
- 매 학습마다 테스트 데이터로도 테스트 → 과적합이 되기 직전을 알 수 있음
- 그래프를 보고 적합한 지점(성능이 좋은 지점)을 확인 → 그 지점까지의 웨이트를 불러와서 그 시점으로 제품을 출시함 = **체크포인트**

내가 수집한 데이터에 AI가 너무 가깝게 학습해서 생기는 것이 원인.

### Drop out

레이어 중간중간 한 부분을 랜덤하게 꺼버리는 것. 입력에서 전달되어도 꺼져있기 때문에 다음 레이어로 전달되는 값이 없음. AI 학습을 의도적으로 방해해서 주어진 데이터에 너무 가깝게 학습되는 것을 방지.

### 문자의 학습

문자(단어)를 숫자로 바꾼 것 ⇒ 벡터. 벡터의 단위가 가까울수록 연관된 단어. **embedding vector** — 어떤 의미를 담고 있는 벡터.

### RNN / LSTM

- **RNN**: 시계열. 단어 하나를 입력한 후 나온 출력을 그다음 입력에 같이 넣음
- **LSTM**: RNN 보강 버전
- 둘 다 현재는 쓰이지 않음 → 트랜스포머 구조의 등장

### ViT, Query / Key / Value

**쿼리(Query), 키(Key), 밸류(Value)**는 데이터베이스에서 정보를 검색하고 조합하는 원리를 차용한 핵심 개념

- **쿼리 (Query)**: 현재 단어가 다른 단어들에게 "내가 지금 무엇을 찾고 있는지" 던지는 질문
- **키 (Key)**: 각 단어가 가지고 있는 "자신의 특징이나 이름표"로, 쿼리의 질문에 얼마나 적합한지 비교하는 기준
- **밸류 (Value)**: 단어가 실제로 품고 있는 "진짜 의미 정보"이며, 쿼리와 키의 유사도(가중치)가 높을수록 최종 결과에 더 많이 반영됨

`sos(start of sentence)` — 특수한 벡터

### 구조 종류

- **Encoder-only**: "이 입력이 무슨 내용이지?" → 이해/분석
- **Decoder-only**: "지금까지 나온 내용을 보고 다음에 뭐가 나오지?" → 생성
- **Encoder + Decoder**: "입력을 이해한 다음, 그걸 바탕으로 새로운 결과를 만들어줘." → 이해 + 생성
