## 1. 기본 평가 지표

| 지표 | 뜻 |
|---|---|
| Accuracy (정확도) | 전체 예측 중 정답을 맞힌 비율 |
| Precision (정밀도) | 정답이라고 예측한 것 중 실제 정답인 비율 |
| Recall (재현율) | 실제 정답 중 AI가 찾아낸 비율 |
| F1 Score | 정밀도와 재현율의 균형을 나타내는 점수 |
| TP / TN / FP / FN | AI의 예측 결과를 네 가지(참 양성·참 음성·거짓 양성·거짓 음성)로 구분한 것 |

### 혼동행렬

AI가 어떤 항목을 맞히고 틀렸는지 정리한 표. 단순히 전체 정답 개수만 보여 주는 게 아니라, **어떤 클래스를 어떤 클래스로 잘못 판단했는지** 보여 준다.

### Macro F1과 Weighted F1

둘 다 여러 클래스의 F1 Score를 평균 내는 방식이다.

| 방식 | 비중 |
|---|---|
| Macro F1 | 모든 클래스에 동일한 비중 |
| Weighted F1 | 클래스의 데이터 개수에 따라 비중을 다르게 줌. 데이터가 많은 클래스의 점수가 전체 결과에 더 큰 영향을 준다 |

## 2. 평가를 위한 용어

| 용어 | 쉽게 말하면 |
|---|---|
| Baseline | 개선 전 성능을 측정한 최초 기준점 |
| Zero-shot | 예시 없이 작업 지시 |
| One-shot | 예시 1개 제공 |
| Few-shot | 작업 전에 예시 여러 개를 보여 줌 |
| Eval (평가셋) | AI의 성능을 객관적으로 측정하기 위한 시험 문제 |
| Data Leakage (데이터 누수) | 시험 문제나 정답이 미리 유입되는 문제 |
| Outscope | 응대 범위를 벗어난, AI가 처리할 수 있는 범위 밖의 질문 |

- **Eval**: 평가에 쓸 질문과 정답을 미리 정해 두고 같은 기준으로 시험하는 것이 중요하다. 그래서 **모델을 만들기 전에 평가셋부터 확정**한다.
- **Data Leakage**: AI가 시험 문제의 정답을 미리 알고 시험을 보는 것과 같다. 평가에 쓸 정보가 학습이나 예시 제공 과정에 미리 들어가 평가 결과가 왜곡된다.

## 3. 라우터와 규칙 기반 분류

**라우터(Router)**는 들어온 질문을 분석해서 적절한 곳으로 보내 주는 역할이다.

**규칙 기반 분류**는 미리 정해 둔 조건과 규칙에 따라 데이터를 분류하는 방식이다. 특정 단어가 포함됐는지 확인해서 문의 유형을 정하고, 규칙을 **순서대로** 확인한다.

```
'반품'이 있으면     → RETURN_REFUND
'배송비'가 있으면   → SHIPPING
어떤 규칙에도 없으면 → OTHER
```

"반품 배송비는 얼마인가요?"에는 '반품'과 '배송비'가 모두 들어 있다. 분류기는 첫 번째 규칙부터 확인하므로 '반품'을 발견하는 순간 RETURN_REFUND로 분류한다. **규칙 순서를 바꾸면 결과도 달라진다.**

### 왜 처음부터 LLM을 쓰지 않을까

LLM을 쓰기 전에 규칙만으로 어디까지 분류할 수 있는지 먼저 확인한다.

1. 규칙만으로 충분히 분류된다면 굳이 LLM을 쓸 필요가 없다.
2. 규칙이 틀리는 사례를 보면 LLM으로 해결해야 할 문제가 무엇인지 알 수 있다.

> 처음부터 복잡한 AI를 쓰는 게 아니라 가장 단순한 방법부터 시도한다.

### 규칙 기반 결과를 분석하는 순서

1. **혼동 행렬 확인** — 어떤 유형끼리 자주 혼동되는가?
2. **오분류 문장 확인** — 실제로 어떤 질문을 잘못 분류했는가?
3. **원인 분석** — 규칙 부족인가? 의도 구분 문제인가?
4. **개선 기준 도출** — LLM 프롬프트에 필요한 기준 찾기

| 방식 | 기준 | 분류 방법 |
|---|---|---|
| 규칙 기반 | 단어 중심 | 정해진 단어와 규칙을 확인 |
| LLM 기반 | 의미 중심 | 질문 전체의 의미와 의도를 파악 |

**Confidence**: AI가 자기 판단에 얼마나 확신하는지 나타내는 값.

## 4. Fail fast

키(API key)가 없는데 경고만 찍고 지나가면, 다음 셀들이 줄줄이 실행되다가 엉뚱한 곳에서 알아보기 힘든 에러가 난다. 그래서 **문제가 생긴 그 자리에서 바로 멈추게** 한다. 이런 방식을 **fail fast**라고 한다.
