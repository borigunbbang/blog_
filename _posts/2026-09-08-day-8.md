## 내가 앱을 만들어서 거기에 내가 구독하는 LLM을 넣을 수 있을까?

- **퍼스트파티** → 클로드 예를 들면 클로드 회사에서 직접 만들어서 배포하는 프로그램

## 한줄정리

- **PRD** - 무엇을·왜 만들지 정리한 기획서 한 장
- **MVP** - 사용자가 핵심 결과 하나를 끝까지 얻을 수 있는 최소 작동 버전
- **목업 데이터** - 진짜처럼 보이는 가짜 데이터 (저장 없이 화면부터 채우는 용도)
- **CRUD** - 데이터 만들기·읽기·고치기·지우기
- **하네스** - AI 코딩 작업을 실행·검토하는 작업 환경 (브라우저형·편집기형·터미널형)
- **환경변수(.env)** - 비밀값을 코드 밖에 보관하는 자리
- **커밋** - 지금 작동하는 상태에 이름을 붙여 복구 지점을 만드는 기록
- **배포** - 내 컴퓨터에서만 보이던 것을 인터넷 누구나 들어오는 주소로 내보내기

## 메인 퀘스트 01, 이것을 향해 간다 - 제출물과 평가 루브릭

이 모듈의 최종 제출(Main Quest 01)과 평가 기준을 오늘 시작하면서 봅니다. 착수 순간부터 제출 기준을 본다는 것 - 이게 프로답게 범위를 잡는 첫걸음입니다.

### 제출물 (이 모듈의 마지막 날 마감)

| 제출물 | 형식 |
|---|---|
| 실행 가능한 웹 서비스 | GitHub 저장소 또는 배포 URL (브라우저에서 동작 확인) |
| 기획 문서 1장 | 마크다운/PDF (서비스 개요·타겟 사용자·해결 문제) |
| 회고록 1장 | 마크다운 (AI와 협업하며 배운 점·어려웠던 점) |
| 시연 영상 | 3분 이내 (직접 서비스를 시연하며 설명) |

### 평가 루브릭 - 오늘 남길 증거

다섯 항목의 증거가 오늘 활동에서 자연스럽게 나옵니다. 따로 챙기려 애쓰지 말고, 한 문장·대화·결정을 그날 기록으로 남기면 나중에 회고와 제출의 근거가 됩니다.

| 항목 | 비중 | 오늘 남겨 둘 증거 |
|---|---|---|
| 도메인 연결성 | 25% | "내 전문 분야의 이 불편을" 으로 시작하는 한 문장 |
| 기능 완성도 | 25% | 오늘 다섯 단계 중 도달한 지점 (어디까지 굴러가나) |
| AI 활용도 | 20% | AI와 주고받은 대화 (지우지 말고 그대로 남기기) |
| 회고 깊이 | 15% | 오늘 결정한 것·참은 것을 적어 둔 회고 노트 |
| 발표/시연 | 15% | 핵심 가치 30초로 말해 보는 연습 |

## 오늘 범위 정하기 (MVP 스코핑)

꼭(Must) / 있으면 좋음(Should) / 나중에(Could) / 지금은 안 함(Won't) 네 가지를 나눠서 적어보기.

- '안 만들 것' 목록을 지키고,
- MVP에서는 Must 단계만

**사용자 불편 정의 템플릿**

> [누가] 가 [어떤 상황/언제] 에 [무엇을 못 해서], [어떤 불편] 을 겪는다.

**오늘 채울 것 (예시: 방송 자막 음향 효과 자동화 서비스)**

| 항목 | 내가 채울 것 | 예시 |
|---|---|---|
| 한 문장 설명 | 내 서비스를 한 문장으로 (한 문장에 안 담기면 범위가 너무 넓은 것) | 방송 자막 음향 효과 자동화 서비스 |
| 핵심 흐름 하나 | 사용자가 처음부터 끝까지 하는 한 가지 (예: 상품 고르기 → 장바구니 → 주문) | 영상 업로드 → 샘플 자막 스크린샷 후 업로드 → 그에 맞는 예시 음향 파일 업로드 |
| 꼭(Must) 3개 | 그 흐름에 반드시 필요한 것 3가지 | 영상, 스크린샷, 음향파일 |
| 지금은 안 함(Won't) 5개 | 이번엔 일부러 빼는 것 5가지 | 더 디테일한 작업 |
| 완성 기준(done) | "이것까지 되면 오늘 성공"의 기준 한 줄 | 영상이 올라가고 같은 자막 2개 이상 효과 적용 완료 |
