## 크롬 개발자 모드 여는 법

- 윈도우: `F11`
- 맥: `Command + Option + I`

## 웹의 기본 3요소

- **HTML** (HyperText Markup Language): 화면에 무엇이 담기는지를 적는 문서
- **CSS** (Cascading Style Sheets): 글씨의 색, 크기를 바꾸는 언어 / 정보가 어떻게 보일지를 정하는 규칙
- **자바스크립트**: 사용자가 무언가를 했을 때 무엇이 바뀔지를 정하는 프로그래밍 언어

사용자와 웹이 인터랙션(텍스트 입력, 버튼 누르기 등)하며 동적인 정보 표현 가능. 자바스크립트 이전에는 정적인 정보만 담겨 있었음 → HTML과 CSS로 단순한 인쇄물 같은 표현만 가능했음. 자바스크립트 등장 이후 웹이 반응할 수 있게 됨 → 버튼을 누르면 그림이 움직임.

- **프론트엔드**: 보이는 영역
- **백엔드**: 안 보이는 영역

## 동기 vs 비동기

**동기**: 하나의 작업이 다 이루어지고 나서 다음 작업이 이루어지는 것 (한 작업이 다 끝날 때까지 다음 작업으로 넘어가지 않음)

- 예) 텍스트 정보 다 뜬 후 이미지도 다 뜨고, 다음 이미지 뜨고 이런 식. 모든 정보가 다 뜬 후에야 웹페이지를 스크롤할 수 있음
- 동기식 작업이 꼭 필요한 경우: 결제 및 거래(잔액 조회 / 결제 요청 / 잔액 차감)

**비동기**: 웹페이지는 텍스트 / 이미지 / 웹스크롤이 다 따로 돌아감 → 오래 걸리는 일을 미리 걸어두고 다음 작업을 진행, 그 후 끝났다는 신호가 오면 결과를 처리

## 스레드 / 프로세스

### 스레드

- 프로세스(작업실) 안에서 일을 처리하는 일꾼
- 페이지 하나를 구성하기 위해 따로따로 돌아가는 작업들
- 같은 프로세스 소속 스레드들은 메모리를 공유함 → 서로 결과를 주고받을 수 있다

### 프로세스

- 실행 중인 프로그램 하나 (독립된 메모리 공간)
- 하나의 프로세스 안에는 여러 스레드가 돌아감
- 프로세스끼리는 메모리 공유 X
- 예) 크롬은 탭 하나하나, 확장 프로그램 하나하나를 별도 프로세스로 띄움 → 탭 하나가 죽어도 다른 탭은 안전

### 멀티프로세싱

- 작업실 자체를 여러 개로 나눠서 처리하는 방식(= 프로세스를 여러 개 씀)
- 장점: 하나가 죽어도 나머지는 안전
- 단점: 무겁고, 프로세스 사이에 재료(데이터)를 주고받는 비용이 큼
- 예) 크롬의 탭들, 앞으로 볼 개발 서버 / 빌드 도구

### 멀티스레딩

- 한 작업실(프로세스)에 여러 명의 일꾼(스레드)
- 메모리를 서로 공유
- 단점: 동시에 같은 메모리를 건드리면 기록이 꼬일 수 있음

## 코어와 시분할

**코어**

- CPU 안에서 실제로 일하는 물리적인 일손
- 코어가 N개면 진짜로 동시에 N가지 일 처리 가능 (예: 14코어 → 14개 동시 처리)
- 한 CPU 안에 코어가 여러 개 있고, 이 코어들이 수많은 프로세스·스레드를 나눠 맡음

**(추가) 시분할(time-sharing)** — 코어 수보다 프로세스·스레드가 훨씬 많은데 안 멈추는 이유

- 코어가 스레드를 아주 짧게 번갈아 실행 → 전환이 빨라서 사람 눈엔 동시에 도는 것처럼 보임
- 1960년대 MIT에서 시작(존 매카시 제안, CTSS로 구현) — "여러 사람이 컴퓨터 한 대를 각자 독차지한 듯 느끼게" 하자는 아이디어
- 여러 사람이 한 컴퓨터를 나눠 쓰면서 파일을 구분할 필요가 생겨 컴퓨터 비밀번호가 탄생한 것도 이 시분할의 부산물

### 확인해보기

- Windows: `echo $env:NUMBER_OF_PROCESSORS`
- macOS: `sysctl -n hw.ncpu`
- → 코어 수와 활동 상태 보기 / 작업 관리자의 프로세스 수를 비교
