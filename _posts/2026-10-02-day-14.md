| 항목 | 내용 |

| 팀명 | 졸린이즈 |
| 팀원 | 3명 (기획/화면, 데이터/서버, 통합/배포) |

### 사용자와 해결할 문제

- **핵심 사용자**: 기업의 재무정보를 직접 찾아 비교하는 데 익숙하지 않은 개인 사용자
- **해결할 문제**: 주식 투자자가 기업을 분석하려면 전자공시에서 사업보고서·분기보고서 등의 데이터를 찾아 직접 비교해야 한다.

### 대표 사용자 시나리오 (입력 → 행동 → 결과)

**시나리오 1. 기업의 재무 추이 분석**

> "삼성전자의 최근 5년 매출액 추이를 보여줘."

- 행동: 삼성전자 식별 → 질문을 최근 5년 / 매출액 / 연도별 추이로 구조화 → 사용 가능한 데이터와 분석 조건 검증 → 전자공시에서 매출액 조회 → 연도별 매출액 계산·정리 → 표와 차트로 변환
- 결과: 연도별 매출액 표, 매출액 추이 선 차트, 사용한 기간과 데이터 범위, 전자공시 데이터 출처, 계산에 사용된 원본 데이터 확인

**시나리오 2. 두 기업의 재무정보 비교**

> "삼성전자와 SK하이닉스의 최근 3년 영업이익을 비교해줘."

- 행동: 두 기업 식별 → 최근 3년 / 영업이익 / 기업 간 비교 추출 → 동일 기간 영업이익 조회 → 동일 기준으로 정리 → 기업별 비교 → 표와 차트 생성
- 결과: 기업별·연도별 영업이익 비교표, 비교 차트, 각 수치의 공시 데이터 근거, 사용된 기간과 지표 표시

**시나리오 3. 전년 대비 변화 분석**

> "삼성전자의 매출액이 전년 대비 얼마나 변했는지 알려줘."

- 행동: 연도별 매출액 조회 → 직전 연도와 연결 → 증감액·증감률 계산 → 검증 → 표와 차트로 표시
- 결과: 연도별 매출액, 전년 대비 증감액·증감률, 매출 변화 추이 차트, 계산에 사용된 데이터 및 산식

### 목표 단계와 이번 주 구현할 기능

목표 단계: **Step 1 핵심 흐름** — 전자공시 데이터를 기반으로 사용자가 기업과 자연어 질문을 입력하면, 실제 데이터를 조회·계산하여 표와 차트, 분석 근거를 제공하는 기능까지 구현한다.

- **기업 선택 및 전자공시 데이터 조회**: 기업명 검색·선택, 전자공시 API로 재무 데이터 조회, 매출액·영업이익 등 기본 재무지표 제공
- **자연어 질문을 통한 재무 데이터 분석**: 질문에서 기업·기간·재무지표·분석 유형 추출, 실제 데이터 기반 추이·증감률 계산, 표와 선/막대 차트 시각화, 데이터와 출처 함께 표시
- **로그인 및 사용량 제한**: 구글 로그인, 최초 로그인 시 약관 동의, 회원별 하루 질문 수 한도 및 남은 질문 수 표시

**통과 기준**: 질문 → 데이터 조회 → 실제 계산 → 표 → 차트 → 근거 표시의 전체 흐름이 배포 환경에서 정상 동작해야 한다.

### 이번 주 하지 않을 기능

- **고급 투자 분석 및 예측**: 주가 상승·하락 예측, 매수·매도 추천, 종목 추천, 뉴스 감성 분석, 복잡한 투자 전략 및 백테스트, 주가 데이터 예측 모델
- **확장·협업 기능**: 여러 데이터셋 결합, 사용자별 프로젝트·권한 관리, 분석 결과 공유, 대시보드 저장·협업, 자유로운 SQL/Python 실행, 대규모 데이터 처리 및 작업 큐

### 역할과 상호 검토

- 기획/화면: 팀원 A
- **데이터/서버: 나**
- 통합/배포: 팀원 B
- 검증/문서: 셋 다

상호 검토 방식: 각자 구현 후 다른 팀원이 배포 환경에서 테스트, 데이터/계산 결과는 담당자가 아닌 팀원이 사전 정답과 비교, AI가 만든 분석 요청이 실제 계산 결과와 연결되는지 검토, 마지막엔 한 명이 전체 흐름을 처음부터 끝까지 직접 테스트.

```
최종 검토 기준
사용자 질문 → AI 분석 요청 → DART 데이터 조회 → 실제 계산 → 표/차트 → 근거 표시
```

## 진행상황 (순서대로)

### WU-101 DB 스키마·RLS·시드

용어 정리부터 했다.

- **DB 스키마 초안**: 데이터베이스를 어떤 구조로 만들지 미리 그려놓은 설계도
- **RLS(Row Level Security, 행 수준 보안)**: 회원 A는 자기 데이터만, 회원 B의 데이터는 볼 수 없게 만드는 것
- **quota_config 10개 키**: 사용량 제한(쿼터) 설정 저장소. 키는 설정 항목의 이름
- **decline_messages**: 거절/불가 상황에서 보여줄 문구 저장소

| 이름 | 역할 | 쉽게 말하면 |
|---|---|---|
| package.json | 프로젝트/패키지 설정 | 📦 필요한 프로그램 목록 + 명령어 |
| tsconfig.json | TypeScript 설정 | ⚙️ TypeScript 사용 규칙 |
| Vitest | 테스트 도구 | 🧪 코드가 제대로 작동하는지 검사 |

**WU-001 가져오기**: 원본 저장소와 내 포크 양쪽 main 모두에 Playwright 버그가 들어있는 상태 → 상황 전달 후 버그 제거된 파일로 다시 싱크포크해서 가져옴.
