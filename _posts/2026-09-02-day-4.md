## 함수 / 변수

**함수**

- 하나의 입력값을 넣으면 정해진 규칙에 따라 결과값을 만들어내는 것
- 사전에 정의되어 있는 함수 / 사용자가 직접 등록한 함수가 있음
- 같은 입력값이라도 함수의 목적에 따라 다른 결과가 나올 수 있음
- 함수 = 입력 → 처리 → 출력

**변수**

- 변할 수 있는 값을 저장해두는 것
- 프로그램을 실행하면서 값이 바뀔 수 있음

**프로그램**: 기본적으로 위에서 아래로, 좌에서 우측으로 실행

**명령어**: 컴퓨터에게 무엇을 하라고 지시하는 것 (명령어 자체를 변수로 사용하는 것은 아님)

## 객체

변수와 함수를 묶어서 하나의 변수처럼 다룸. 변수 + 함수 ⇒ 변수

```
객체
├── 변수(데이터)
└── 함수(기능)
```

객체 = 관련된 데이터와 기능을 하나로 묶어놓은 것

```
SFX
├── 이름 : Explosion.wav
├── 길이 : 3초
├── 카테고리 : Explosion
└── 재생하기()
```

객체와 객체는 서로 영향을 받음

## 프레임워크

웹페이지가 점점 복잡해짐(여러 코드의 실행이 필수적) → 이러한 웹 페이지의 뼈대/틀. 큰 틀 안에 어떤 내용이 들어가는지 규칙으로 정해놓고 내용만 넣으면 구현이 되도록 만드는 것.

- **컴포넌트**: 한 번 만들어 여러 곳에서 사용하는 화면 부품 → 반복을 줄임
- **스테이트(State)**: 현재 화면이 어떤 상태인지 기억하는 값. State를 바꾸면 그 State에 연결된 화면도 같이 바뀌게 만드는 것 → 변화 관리를 도움
- **Routing**: URL과 화면을 연결하는 것. 주소와 화면을 연결하는 규칙 하나하나를 라우트(route)라고 부르고, 그 라우트들을 여러 개 모아서 관리하고 실제로 작동시키는 것 전체를 라우팅(routing)이라고 함 → 여러 화면을 연결

| 문제 | 프레임워크가 도와주는 것 |
|---|---|
| 같은 걸 계속 만듦 | 컴포넌트 |
| 하나가 바뀌면 여러 곳이 바뀜 | 상태(State) |
| 페이지가 많아짐 | 라우팅(Routing) |

## 추상화

내부적인 복잡한 기능이 드러나지 않고 숨겨져 있음 → 꼭 필요한 조작만 밖으로 드러냄. 입력과 출력 정도만 알고 가져다가 쓰는 느낌.

**DOM (Document Object Model)**: 문서 객체 모델 / 문서를 논리적 트리로 표현. 구조화되어 있고, JavaScript는 이 DOM을 이용해서 화면의 요소를 읽거나 변경할 수 있음.

## 프론트엔드 / 백엔드

**프론트엔드**: 사용자가 보고 직접 사용하는 부분

```
프론트엔드
├── 컴포넌트
│      └─ 화면을 부품으로 나눔
├── State
│      └─ 현재 상태를 관리
├── Routing
│      └─ URL과 화면 연결
└── Framework
       └─ 위 작업들을 체계적으로 관리
```

**백엔드**: 사용자가 직접 보지는 않지만, 서비스 뒤에서 데이터를 처리하는 부분

**서버**: 백엔드와 완전히 별개의 단계라기보다는, 백엔드 프로그램이 실행되는 컴퓨터/환경을 의미하는 경우가 많음.

```
                웹서비스
                   │
      ┌────────────┴────────────┐
      │                         │
  프론트엔드                  백엔드
  (사용자가 봄)              (데이터 처리)
      │                         │
   React                     서버
   Vue                       DB
   Svelte                     │
      │                       │
      └──────── API ───────────┘
                 │
               JSON
                 │
           데이터 주고받기
```

프론트엔드 개발을 하기 위해선 요청을 보내고 돌아오는 응답이 있어야 처리 가능. API를 사용해서 요청하고 응답을 받음.

## API / JSON / Mock Data

**API (Application Programming Interface)**: 프로그램끼리 대화하는 창구.

프론트엔드와 백엔드가 개발 전에 미리 이러한 규격으로 하자고 먼저 정한 후 각자 개발에 들어감 → 프론트엔드는 그 가상의 규격으로 미리 목업 데이터(가상의 백엔드)로 개발한 것을 테스트함 → 최종에서 목업 데이터를 지우고 실제 데이터를 처리함.

### 기본 명령

| 명령 | 의미 | 예 |
|---|---|---|
| GET | 가져오기 | SFX 목록 가져오기 |
| POST | 새로 만들기 | SFX 등록 |
| PUT | 수정하기 | SFX 정보 수정 |
| DELETE | 삭제하기 | SFX 삭제 |

식당에 비유하면:

- GET → "메뉴판 보여줘"
- POST → "이 메뉴 하나 주문할게"
- PUT → "내 주문 내용 바꿔줘"
- DELETE → "주문 취소할게"

**JSON**: 프로그램끼리 데이터를 주고받을 때 사용하는 정해진 데이터 표현 방식 = API로 데이터를 주고받을 때 많이 사용하는 데이터 표현 방식.

**목업 데이터 (Mock Data)**: 진짜 데이터인 것처럼 만들어놓은 가짜 데이터.

> 예) 실제 DB가 아직 없다고 해봅시다. "SFX 파일 30개가 있는 것처럼 가짜 데이터를 만들어줘." 라고 할 수 있습니다.
>
> Explosion.wav / Footstep_01.wav / Door_Open.wav / Rain_Loop.wav / ...
>
> 이런 데이터를 만들어 놓고 실제 서비스처럼 화면을 테스트합니다. 백엔드가 완성될 때까지 기다릴 필요가 없음 → 일단 화면부터 실제처럼 작동하게 만든다.

```
① 프론트엔드 / 백엔드가 어떤 데이터를 주고받을지 약속
             ↓
② 백엔드가 아직 없어도 Mock Data를 만듦
             ↓
③ 프론트엔드 개발
             ↓
④ 화면 / 기능 테스트
             ↓
⑤ 백엔드 완성
             ↓
⑥ Mock Data 제거
             ↓
⑦ 실제 API 연결
             ↓
⑧ 실제 DB 데이터 사용
```

## 오늘의 용어 정리

- 함수 = 입력을 받아 정해진 일을 하고 결과를 내는 것
- 변수 = 변할 수 있는 값을 담아두는 것
- 객체 = 관련된 데이터와 기능을 하나로 묶어놓은 것
- 프레임워크 = 웹서비스를 만드는 뼈대
- 컴포넌트 = 화면을 재사용 가능한 부품으로 나누는 것
- State = 화면의 현재 상태를 관리하는 것
- Routing = URL과 화면을 연결하는 것
- API = 프론트엔드와 백엔드가 대화하는 약속된 창구
- JSON = 데이터를 주고받는 형식
- Mock Data = 백엔드가 없어도 개발할 수 있게 만든 가짜 데이터
- React / Vue / Svelte = 화면을 만드는 서로 다른 접근법
- Next.js = React를 기반으로 실제 웹서비스를 만들기 위한 더 큰 틀
