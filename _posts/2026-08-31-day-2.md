## git diff (깃디프) 명령이란?

git diff는 작업 디렉토리(또는 커밋 간)의 변경 내용을 비교해서 보여주는 명령. 파일의 형식에 상관없이 적용 가능(텍스트 파일 등) → 변경된 사항을 확인 가능.

### 기본 사용법

- `git diff` — 작업 디렉토리(수정했지만 아직 git add하지 않은 파일)와 스테이징 영역(인덱스) 간의 차이를 보여줌
- `git diff --staged` (또는 `--cached`) — 스테이징된 변경 내용과 마지막 커밋 간의 차이를 보여줌
- `git diff HEAD` — 작업 디렉토리와 마지막 커밋 간의 모든 변경(스테이징 여부 무관)을 보여줌

### 커밋/브랜치 비교

- `git diff commit1 commit2` — 두 커밋 간의 차이
- `git diff branch1 branch2` — 두 브랜치 간의 차이
- `git diff HEAD~1 HEAD` — 직전 커밋과 현재 커밋 비교

### 특정 파일만 보기

- `git diff -- 파일명` — 특정 파일의 변경 내용만 표시

내가 원하는 의도와 맞게 수정되었는지(잘못 삭제하거나 변경된 내용이 있는지) 코드 확인 작업 및 합치는 작업에서 사용.

## 버전관리에서의 브랜치 역할

버전 관리(Git 등)에서 브랜치는 하나의 코드베이스에서 여러 작업 흐름을 독립적으로 관리할 수 있게 해주는 역할.

- 메인 브랜치에 영향을 주지 않고 독립적으로 커밋을 쌓아갈 수 있다 (병렬 작업)
- 작업이 끝나면 `git merge`나 `git rebase`로 브랜치의 변경 사항을 다시 메인 브랜치로 합침
- 합치기(merge)의 명확한 기준점 확인 가능

## 깃과 깃허브의 차이점

**Git**

Git은 버전 관리 시스템(VCS) 자체예요. 리누스 토르발스가 만든 오픈소스 소프트웨어로, 컴퓨터에 설치해서 로컬에서 파일 변경 이력을 추적하고 관리하는 도구입니다. 인터넷 연결 없이도 커밋, 브랜치, 병합 같은 모든 버전 관리 작업을 할 수 있어요. `git commit`, `git branch`, `git merge` 같은 명령어를 실행하는 프로그램 자체가 Git이라고 보면 됩니다.

**GitHub**

GitHub는 Git 저장소를 온라인에 호스팅해주는 웹 서비스예요. 마이크로소프트가 소유한 클라우드 플랫폼으로, Git으로 관리하는 코드를 인터넷 상에 올려서 팀원들과 공유하고 협업할 수 있게 해줍니다. 코드 저장 외에도 이슈 트래킹, 풀 리퀘스트(PR)를 통한 코드 리뷰, GitHub Actions(CI/CD), 프로젝트 보드 같은 협업 기능을 추가로 제공해요.

**비유하자면**

Git이 문서 작업의 "버전 저장 기능" 자체라면, GitHub는 그 문서를 클라우드에 올려서 여러 사람과 공유하고 코멘트를 주고받을 수 있는 "구글 드라이브" 같은 서비스예요. Git 없이는 GitHub를 쓸 수 없지만, Git은 GitHub 없이도 로컬에서 완전히 독립적으로 사용할 수 있습니다.

## 터미널에 대해

파일경로 - 프롬프트. 명령어를 사용해서 모든 동작을 수행함 (폴더 이동, 복사, 삭제, 파일 생성 등등).

`touch 파일명` → 파일명에 해당하는 빈 파일이 만들어짐 (윈도우엔 없는 명령 → `New-Item` 사용)

| 명령 | 하는 일 |
|---|---|
| `pwd` | 지금 내가 있는 폴더의 전체 경로를 출력합니다. |
| `ls` | 현재 폴더 안의 파일·폴더 이름을 보여 줍니다. |
| `cd 폴더이름` | 지정한 폴더로 이동합니다. `cd ..`는 한 단계 위로 갑니다. 경로를 한번에 입력할 수도 있습니다. (예: `cd c:\aiffel_`) |
| `mkdir 폴더이름` | 새 폴더를 만듭니다. |
| `touch 파일이름` | 빈 파일을 만들거나, 기존 파일의 수정 시각을 갱신합니다. |
| `rm 파일이름` | 기존 파일을 삭제합니다. |
| `mv 원본 대상` | 파일·폴더를 이동하거나 이름을 바꿉니다. 실행 전 원본과 대상을 꼭 확인합니다. |
