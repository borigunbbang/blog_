## 1. LLM (거대언어모델)

트랜스포머(Transformer) 구조를 기반으로 하는 모델.

순수 LLM 자체는 상태(state)를 저장하지 않음(stateless): 입력을 넣으면 출력을 한 번 뱉을 뿐, 자체적으로 이전 대화를 기억하는 기능이 없음. (겉보기에 "기억하는 것처럼" 보이는 건 하네스가 이전 대화 내용을 매번 다시 입력에 끼워 넣어주기 때문.)

## 2. 챗봇 · 어시스턴트 · 에이전트

그래서 "단순 챗봇"은 에이전트라고 부르지 않음. 에이전트인지 여부를 가르는 핵심은 "자율적으로 여러 단계를 반복하며 계획을 수정하는가"입니다.

에이전트의 대표적인 동작 루프는 **생각(Thought) → 행동(Action) → 관찰(Observation)**을 반복하는 방식(ReAct)이며, 여기에 "반성/자기평가(Reflection)" 단계까지 추가한 확장된 방식도 있습니다.

루프를 무한정 많이 돌린다고 결과가 좋아지는 건 아님. LLM이 한 번에 참고할 수 있는 입력량(컨텍스트 윈도우)은 정해져 있어서, 입력이 이를 초과하면 오류가 나거나 성능이 떨어짐. 루프가 길어질수록 불필요하거나 잘못된 정보가 계속 쌓여 오히려 결과가 나빠질 수 있음.

| 구분 | 특징 |
|---|---|
| 챗봇 (Chatbot) | LLM + 대화 기록을 관리해주는 하네스. 이전 대화 맥락을 기억하고 답할 수 있지만, 도구를 스스로 골라 실행하거나 여러 단계를 계획하지는 않음. |
| 어시스턴트 (Assistant) | 챗봇 기능 + 도구(검색, 계산 등) 호출 가능. 다만 스스로 다단계 계획을 세우고 반복 실행하는 자율 루프는 돌지 않음. |
| 에이전트 (Agent) | 목표 달성을 위해 스스로 판단·계획·실행·반복하는 시스템. 모델 + 하네스(도구, 메모리, 루프 제어 등)로 구성됨. |

## 3. MCP (Model Context Protocol)

<https://registry.modelcontextprotocol.io>

AI(LLM)와 외부 서비스/도구를 연결하기 위한 표준 통신 규약.

MCP가 있으면 서비스마다 각각 커스텀 연동을 개발할 필요 없이, 표준화된 방식으로 붙여서 쓸 수 있음. (구글, 노션 등 서비스별로 따로 개발하지 않고 MCP 규격에 맞춰 연결)

비유하자면 PC에 USB를 꽂는 것과 비슷함 (Anthropic도 실제로 "AI를 위한 USB-C 포트" 같은 개념이라고 설명함).

단점: 도구 목록/설명이 계속 컨텍스트에 실리기 때문에 토큰을 많이 소모하고, 상대적으로 느릴 수 있음.

- **도구(Tools)** - AI가 실행하는 기능 (예: 검색하기, DB 조회하기)
- **자원(Resources)** - AI가 읽어 들이는 데이터 (예: 파일, 문서, 기록)
- **프롬프트(Prompts)** - 미리 만들어 둔 요청 템플릿

## 4. 스킬 (Skill)

SKILL.md처럼 마크다운 문서 형태로 저장되는, 반복 작업을 위한 "작업 지침서/작업명세서".

AI에게 여러 스킬을 등록해두면, 작업을 시켰을 때 그중 적절한 스킬을 찾아와서 그 지침대로 일함.

AI가 매번 스킬 전체 내용을 다 훑어서 적합한 걸 고르면 토큰이 많이 듦 → 이를 막기 위해 각 스킬 문서 맨 위에 이름(name)과 설명(description)만 요약해두고, AI는 우선 이 요약만 보고 필요한 스킬인지 판단한 뒤, 선택된 스킬의 전체 내용만 그때 불러와서 사용함.

남이 만들어 놓은 스킬을 가져다 쓸 수도 있음 (예: Anthropic이 GitHub에 공개한 예시 스킬들).

예외적으로 CLAUDE.md / AGENTS.md 같은 파일은 스킬처럼 "선택"되는 게 아니라 항상 무조건 불러와서 적용되는 규칙 파일로 취급됨.

| 내가 원하는 것 | 무엇을 쓰나 |
|---|---|
| AI에게 새 능력·연결을 주고 싶다 (내 DB·도구에 붙이기) | MCP |
| AI가 항상 이런 식으로 행동하게 하고 싶다 | 규칙 (프로젝트 설정 파일: CLAUDE.md / AGENTS.md) |
| 반복하는 다단계 작업을 자동화하고 싶다 | 스킬(Skill) |

## 5. 하네스 (Harness)

AI(LLM)를 어떻게 사용할지 감싸고 관리해주는 실행 환경/도구 모음. (메모리 관리, 도구 실행, 스킬 매칭, 루프 제어 등을 담당)

스킬이 여러 개 등록돼 있으면, 하네스가 각 스킬의 이름+설명만 추려서 LLM에게 먼저 보여주고, LLM이 "이 스킬이 필요하다"고 판단하면 그제서야 하네스가 해당 스킬의 전체 내용을 가져와 LLM에게 넘겨줌.

- **터미널/CLI형** - 검은 명령창에서 돌아갑니다. 깊고 강력하지만 조금 낯섦. 예: Claude Code, Codex CLI, Antigravity CLI(agy), Aider, OpenCode
- **편집기(IDE)형** - VS Code 같은 코드 편집기 안에서. 예: Cursor, Devin Desktop(Windsurf에서 개명), Cline. (Roo Code 확장은 2026-05-15에 종료됨.)
- **브라우저형** - 웹에서 클릭 몇 번으로, 처음엔 가장 수월함(배포까지 한 번에). 예: Lovable, Bolt, Replit Agent
- **클라우드/비동기형** - "이 이슈 고쳐 줘"를 통째로 맡기면 백그라운드에서 일하고 결과를 초안으로 가져옵니다. 예: Devin, Google Jules, OpenAI Codex(클라우드)

| 도구 | 형태 | 강점 | 언제 / 누구에게 |
|---|---|---|---|
| Claude Code | 터미널 에이전트 | 깊은 추론·큰 코드베이스·긴 작업, 확장(MCP·스킬·훅)·에이전트 팀 | 어려운 문제를 끝까지 파고들 때 |
| OpenAI Codex | 터미널 + 클라우드 | 이슈를 백그라운드로 맡기고 결과를 받아 옴 | 돌려 두고 결과만 검토할 때 |
| Google Antigravity(agy CLI + 데스크톱) | 터미널·에이전트 환경 | Gemini CLI를 이어받은 Google 통합 도구(2026-06 전환) | Google 생태계로 작업할 때 |
| Aider · opencode | 터미널·오픈소스(BYOM) | 무료, 모델 골라 씀, git 자동 커밋 | 비용을 직접 조절하고 터미널이 편할 때 |

| Cursor | 편집기(VS Code 포크) | 편집 경험이 가장 매끄럽고 자동완성·비주얼 diff가 강함 | 편집기에서 매끄럽게 쓰고 싶을 때 |
| Devin Desktop(구 Windsurf) | 편집기/데스크톱 | 로컬 에이전트와 편집 환경을 함께 | 편집기 안에서 에이전트를 쓰고 싶을 때 |
| Zed | 편집기(고속·무료 티어) | 빠르고 가볍고 모델을 가리지 않음 | 가벼운 편집기를 원할 때 |
| GitHub Copilot | 여러 편집기의 확장 | 가장 널리 쓰이고 기업 보안·감사·정책이 성숙, 저렴 | 회사 규정·컴플라이언스가 중요할 때 |

| OpenClaw · Hermes | 자기개선·개인 비서형(오픈소스) | 챗앱으로 부리고, 기억을 남기며 스스로 스킬을 만듦 | 늘 켜 두는 '내 에이전트'를 원할 때 |
| Lovable · Bolt · Replit | 브라우저(노코드) | 클릭으로 만들고 바로 배포 | 코딩이 처음이거나, 기획자의 첫 도구 |
| Devin · Google Jules | 클라우드/비동기 | 이슈를 통째로 맡기면 알아서 처리 | 결과만 검토하며 맡기고 싶을 때 |

## 6. 컨텍스트(Context)와 멀티턴(Multi-turn)

컨텍스트: LLM이 한 번의 응답을 만들 때 참고하는 입력 전체의 양(대화 기록, 도구 실행 결과 등 포함). 이 양에는 한계(컨텍스트 윈도우)가 있음.

실전 팁: 대화가 길어져 컨텍스트가 꽉 차갈 때는 "새로운 채팅으로 이어서 작업할 건데, 지금까지 내용을 요약해줘" 같은 식으로 요약본을 받아서 새 대화로 넘기는 방법을 씀.

멀티턴(Multi-turn): 하나의 대화 세션 안에서 사용자와 AI가 여러 차례 질문-응답을 주고받는 것. (❌ 여러 종류의 AI를 옮겨 다니며 작업하는 것이 아님)

## 7. 플러그인 (Plugin)

스킬, MCP, 도구 등을 하나로 묶어서 설치할 수 있게 만든 패키지 단위.

여러 플러그인을 모아 놓은 곳을 **마켓플레이스(marketplace)**라고 부름. → 여기에서 설치할 수 있음

```bash
# 마켓플레이스(플러그인 모음)를 하나 등록하고
/plugin marketplace add anthropics/claude-plugins-community
# 거기서 원하는 플러그인을 설치
/plugin install <플러그인이름>@claude-community
```

특정 업무(예: 특정 직무, 특정 회사 워크플로우)에 맞는 플러그인 하나를 설치하면, 관련된 스킬/MCP/도구가 한 번에 세팅되는 개념.

## 8. 랄프 루프 (Ralph Loop)

에이전트에게 정교한 다단계 계획을 미리 짜주지 않고, 같은 지시(프롬프트)를 반복해서 계속 내려 스스로 알아서 조금씩 작업을 진행시키게 만드는 운용 방식.

한 번의 실행으로 작업이 안 끝나도, 루프를 돌 때마다 진행 상황(코드/결과물 등)을 남기고 다음 루프에서 이어받아 계속 다듬어 나감.

공식 용어라기보다 커뮤니티에서 붙은 이름이며, 위 2번에서 언급한 "루프가 많다고 무조건 좋은 게 아니다"라는 한계는 여기에도 그대로 적용되므로, 보통 멈추는 조건(종료 조건)이나 검증 단계를 같이 설계함.
